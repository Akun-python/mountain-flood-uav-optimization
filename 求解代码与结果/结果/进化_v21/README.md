# 进化 v21 — 中继能源组件充电模型按题目附录 2 修正（满充复用 + 6 组件池）

本轮依据"第一性原理 + 条件理解审计"对 P3 中继时序模型做**架构级正确性
修正**，并复核全部论文数字在该修正下不变（保证准确优先于数字变动）。

## 发现的模型偏差（条件理解审计）

**题目附录 2 明文（已从题面 docx 原文逐字核对）**：

> "初始时刻 SOC 均为100%，任务结束后的剩余 SOC 根据可用能量和实际能耗计算，
> 且不得低于返航电量下限；**再次投入任务前应充至100%**。两类能源资源统一
> 采用两阶段等效充电模型……同一资源的任务占用与充电时段不得重叠，不同资源
> 可并行充电。"

中继能源组件参数（`中继无人机数据.xlsx`）：**6 个组件**，等效完全充电时间
T_full=1800 s。

**原实现偏差（v12 引入、v12–v20 沿用）**：`p3_co2.machine_penalty` 用
`charge_from_to(soc_prev, need)` 按下一班所需荷电**部分充电**（"按需补电"），
且每架中继无人机只跟踪**单个**能源组件。两处均违反题面条款：
1. 部分充电 ⇒ 组件未充至 100% 即再次投入任务；
2. 忽略 6 组件共享池 ⇒ 错误地让北点班受东点班组件充电进度约束。

**量化后果**：东点班返航荷电 68.5%（e=1.009/3.2），满充需 910 s；东点返场
4433 s → 北点派单 5429 s 间扣除 300 s 周转仅余 696 s。若按"单组件必须满充"
口径，北点班不可行；按需补电"恰好"掩盖了此缺口（补到 42% 需 0 s）。

## 修正后的模型（v21，与题面一致）

- **组件池**：6 个能源组件共享（R1/R2 均可取用），不同组件可并行充电；
- **满充复用**：组件占用架次后 SOC=1−e/E_use，再次投入任务前必须用两阶段
  曲线充至 100%（`charge_time(soc_end, T_full)`），组件的任务占用与充电时段
  不重叠；
- 每架次选"满充完成最早"的组件（贪心对可行性最优；架次数 ≤ 6 时天然换新
  组件，等价于零充电等待）；
- 无人机时间线不变：180 s 准备 + 30 s 建链 + 300 s 架次周转。
