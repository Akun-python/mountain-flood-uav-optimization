# D题 建模与求解框架设计（v1，随 v37–v58 演进固化）

## 1. 问题形式化建模

**决策变量**：装箱矩阵 X = {x_{j,r}}（箱 j 分配到趟 r）+ 机型分配 y_r ∈ {A,B,C} + 趟启动时刻（由 EDF 排程决定）。

**目标（用户优先序：及时性 > 全部任务完成时间 > 运输能耗 > 架次数）**：
```
min  (1) tardy = 0                  （硬：零违规）
     (2) makespan = max_chain 返场  （第二优先）
     (3) E = Σ趟能耗                 （第三优先）
     (4) |架次 - 23|（第四，可选）
```
分层目标通过硬门槛 + 词典序实现：违规/电池/hard 不满足 → 解不可行（不入比较）。

**硬约束（每次求解均双重校验 dispatch_compliant + check_battery）**：
| 约束 | 建模 |
|---|---|
| 质量 | 每趟 Σ箱质量 ≤ 机型载重（A25/B30/C80 kg） |
| 体积 | 每趟 Σ箱体积 ≤ 机型舱容（A0.058/B0.071/C0.25 m³） |
| 能量 | 每趟能耗 ≤ (1-ρ)·E_use（A4.5/B4.0/C8.0 kWh），ρ=0.2 保底 |
| 电池 | 电池最早可用 = 返场+充电(charge_time)；趟须在 start 前就绪；池化共享 8A/4B/4C |
| 时限 | 每趟 critical = min(deadline_first, deadline_exp)，EDF 排程，投递 ≤ critical |
| hard | 超期箱（期望 10800 也晚）判 hard_ok |
| 交接 | handover 包含在返场时刻 |

**完工下界建模**：makespan ≥ max_pool T_pool/n_pool + 电池间隙；实测 29 架 B/C 4 台必需负载 25901s → 每台 6475.4s + 充电 ≈ 6900–7200s（6990.1 已逼近）。

## 2. 整体求解框架（分层流水线）

```
① 装箱（初始组批）→ ② 排程（EDF + 电池 pool）→ ③ 改进（启发式/RL）→ ④ 联合（P3 中继）
```
- **② 排程**：dispatch_compliant（EDF 键 (critical, -priority, fid) + 电池就绪检查），独立 check_battery 复核
- **③ 改进算子集**（完备性审计）：迁移（同区箱挪趟）/ 换型（A↔B↔C）/ 拆分（满载→A/B 子趟）/ 合并（2趟→跨区1趟，启发式已试全升）/ swap（同区双箱互换，v47 修复）
- **③ 改进算法谱系**：v46 局部搜索（收敛 7724.9）→ v54 换型贪心（7148.2）→ v57 束搜索（7148.2，无迁移算子）→ **v58 Rainbow（6990.1）**：RL 学"暂时恶化"多步路径，独立发现启发式遗漏改进（158s）
- **④ P3 联合**：SA 调中继（seed77 联合最优 7779.2s，零迟到）
