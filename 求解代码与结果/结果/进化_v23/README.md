# 进化 v23 — 跳出偏移搜索盆地：联合完工 7259.81 → 6959.8 s（-4.1%）

## 突破点（架构式改进）

v19–v22 反复验证"联合完工可行下界 7259.81 s"，均以 SA 联合完工最小化的收敛值为准。
本轮从第一性原理重新审视偏移结构，发现**官方偏移的"整体 +300 平移"是搜索盆地而非
可行性要求**：

- 诊断：26 架次中 21 架次的释放偏移使派单恰好比问题二原排程晚 300\,s——这
  +300 由最早 W 区任务（f34 的 S001 段，原始 778\,s）不得早于中继到位所触发。
  但中继最早可于约 603\,s 就位（派发 180 + 出航 393），覆盖原始 778\,s 任务
  完全可行——+300 均匀平移并非必需。
- 直接验证：把 f34 偏移清零仅得 1.1\,s 收益（C 机链由资源门控而非 f34 释放
  门控），进一步证明 +300 与可行性无关。
- 多起点搜索（`p3_minoffsets23.py`：零偏移 / 仅 {f4,f22} 释放 / 官方偏移三个
  起点 × 1500 迭代）：从仅 {f4:3600, f22:1200} 的 7087\,s 盆地逃逸到
  **联合 6959.8\,s**，严格可行（cover\_bad=0、R2\_overlap=0、machine\_pen=0、
  hard\_ok、零迟到、26 架）。

## 采纳方案（干净偏移）

仅两架次施加正偏移：**f4 后移 3300\,s、f22 后移 1000\,s**（北点窗口对齐，
北点任务须晚于东点班结束 3774\,s + R2 周转 300\,s），其余 24 架次零偏移，
派单与问题二冠军排程一致（f9、f11 因电池链联动小幅顺延）。
