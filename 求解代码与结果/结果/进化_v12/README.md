## 已确定结论（方向 ① ⑤）

- **方向 ①**：更大预算与更多种子下，完工口径冠军仍为 balanced/s11 的
  26 架 / 6959.8 s / 70.71 kWh，未被超越；能耗口径端点不变
  （19 架 / 7920.1 / 60.40；21 架 / 7837.0 / 62.46）。冠军在更大搜索空间内
  仍是完工口径最优，说明 26 架方案已接近该口径的搜索极限。
- **方向 ⑤**：同参数族（balanced、seed 11 加 17k）5 次重跑仅 1 次精确复现
  26 架冠军（rep1: 6959.8/70.71/tardy 0），其余 4 次收敛到 25–29 架
  （7449–7893 s）的可行解，其中 2 次仍有迟到。结论：冠军是真实存在的高质量
  解（非随机错误），但搜索具有随机性，需要强化搜索保证取到；论文已相应修正
  （9_evaluation 复现表述、6_problem2 强化搜索描述改写为五元启发式并行口径）。

## 方向 ② ALNS 机队并行度感知（负结果，已闭环）
- 改进：新增 alns_fleet.py——修复算子中按各机型累计飞行时长做机型负载均衡
  （紧急箱专用架次与新建架次选机型时偏向负载最低的机型），其余算子与 alns.py 相同。
- 结果：Budget 20000 下，标准 ALNS 与机队均衡 ALNS 各 2 个种子全部收敛到
  相同的初始解（33 架 / 8651.4 s / 86.82 kWh / tardy 295.6），4 次运行指标
  完全相同，说明两种 ALNS 均未离开初始解、无法与 Tabu 冠军（26 架 /
  6959.8 / 70.71）竞争。修复算子层面的机型均衡不足以改变 ALNS 在该问题
  结构上的失效模式（破坏-修复后总被接收准则拒绝）。ALNS 保持为对照方法，
  论文口径不变。

## 方向 ③ 中继窗口压缩（负结果，已闭环）
- 改进：p3_co2.py 的 evaluate 目标增加可选中继能耗权重 w_relay（默认 0 保持
  原行为），重跑 SA（3000 迭代）。
- 结果：w_relay=0（基准复现）与 0.8、2.0 三个权重全部收敛到同一解——
  W [1078,6802] 1.979、E [1406,4074] 1.046、N [5894,6446] 0.521 kWh，
  合计 3.55 kWh，cover_bad=0。中继窗口由需中继服务段的时空跨距直接决定，
  在保持全覆盖与运输口径不变的前提下，单纯架次平移无法进一步压缩，
  3.55 kWh 为当前方案稳定值；若需更低中继能耗，必须结构调整（边缘段
  改由直连或邻点承担），超出纯平移协同的可行域。
- 结论：P3 时段/能耗数字维持论文口径不变（3.55 kWh）。
